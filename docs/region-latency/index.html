AVD region latency

Ranks Azure regions by round-trip time from this browser, then builds the Cloud Shell commands for the AVD landing zone preflight and deployment in the region you pick. Run it from where your users work, not from Cloud Shell or a VPN.

1. Measure

Takes about 20 seconds. Each region gets a warm-up request and 5 timed ones.

2. Pick a region

Median HTTPS round trip. The fastest region is selected; click a row to pick another. Under 100 ms is good for AVD, 100–150 ms is usable, above 150 ms feels sluggish.

Preflight: repeat until it comes back clean

How to read this

    
    
      
  • Each region is timed with small HTTPS requests to its regional Azure AI services endpoint. That's the network round trip plus a few milliseconds of server time, so treat the numbers as an upper bound and compare regions with each other.
    • 
      
  • A VPN, a secure web gateway (Zscaler, Netskope and the like) or a proxy sends traffic through its own path. Measure the way your users' desktops will actually connect.
    • 
      
  • The landing zone puts the host pool in the same region as the session hosts, so the region must offer AVD host pools. The preflight checks that, along with VM size and quota, the profile storage SKU and existing resources. If the closest region fails it, pick the next one.
    • 
      
  • The parameter files deploy without availability zones, which works in every region. For zone redundancy, edit availabilityZones and profileStorageSku in the file first.
    • 
      
  • Nothing leaves your browser except the timing requests. Your group names are only kept in this browser.
